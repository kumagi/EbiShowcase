THE UPDATE / DRAW BOUNDARY

Separate State Updates from Screen Projections

1

Update owns state mutation

Detects key and touch inputs, and updates game state—positions, HP, gauges, timers, boards, and queues. Collision resolution and queue logic live here.

detect input → evaluate rules → mutate state
2

Draw owns visual projection

Reads the current game state and projects figures, text, and effects into screen pixels. It never mutates game state.

read state → project pixels

Implement gameplay rules in Update (or pure helpers called by Update). Keep Draw strictly as a projection of that state.
